# Internationalisation

The app ships 10 UI languages without any i18n framework. Everything lives in `lib/i18n/` and two client components.

| Code | Language | `Intl` tag |
|---|---|---|
| `fr` (default) | Français | `fr-FR` |
| `en` | English | `en-GB` |
| `es` | Español | `es-ES` |
| `it` | Italiano | `it-IT` |
| `de` | Deutsch | `de-DE` |
| `pt` | Português | `pt-PT` |
| `nl` | Nederlands | `nl-NL` |
| `el` | Ελληνικά | `el-GR` |
| `no` | Norsk | `nb-NO` |
| `da` | Dansk | `da-DK` |

## How the locale is chosen

1. Cookie `fas-locale` (`LOCALE_COOKIE_NAME`), set client-side by `LocaleProvider.setLocale` with `max-age` 1 year, `path=/`, `SameSite=Lax`.
2. Anything else (missing/unknown cookie) → `fr` via `resolveLocale`.
3. No `Accept-Language` sniffing, no URL prefix (`/en/...` does not exist), no per-user DB preference.

Switching language calls `router.refresh()` so server components (layout metadata, dashboards) re-render with the new cookie.

## Files

| File | Role |
|---|---|
| `lib/i18n/locales.ts` | `LOCALES` list (code, flag, label), `SupportedLocale` type, `resolveLocale`, cookie name |
| `lib/i18n/copy.ts` | **Main dictionary** — `dictionaries[locale]` with namespaces `brand`, `localeSwitcher`, `nav`, `footer`, `common`, `home`, `login`, `signup`, `skippers`, `missions`, `verifyEmail`, `messages`, `notifications`, `account`, `availability`, `profile`, `passwordInput`. `getCopy(locale)`. FR is written multi-line; other locales are single-line objects. Declared `as const`, so keys are type-checked against FR only implicitly — a missing key in another locale is **not** a compile error unless a consumer reads it with a narrowed type. |
| `lib/i18n/extra.ts` | **Second dictionary** added later, with an explicit `ExtraCopy` type (so every locale must implement every key). Namespaces `common`, `errors`, `missionsNew`, `profile`, `account`, `onboarding`, `notifications`, `legal` (CGU / privacy / cookies / legal notice content). `getExtraCopy(locale)`. |
| `lib/i18n/options.ts` | Translates **domain enum values** for display: `localizeZone`, `localizeBoatType`, `localizeMissionType`, `localizeRole`. Falls back to the raw stored value. |
| `lib/i18n/format.ts` | `formatDateForLocale`, `formatDateTimeForLocale` using `Intl.DateTimeFormat` and the tag map above. |
| `lib/i18n/server.ts` | `getRequestLocale()` / `getRequestCopy()` — read the cookie via `next/headers` (server components only). |
| `lib/phone.ts` | Has its own `PHONE_COPY` table for validation messages. |
| `lib/onboarding.ts` | ⚠️ `missingRoleFields` returns **French-only** strings. |
| `lib/profile.ts` | ⚠️ `formatAvailabilitySummary` / `indicativeRateLabel` contain French-only literals. |
| `components/LocaleProvider.tsx` | React context exposing `{ locale, setLocale, copy }`; `useLocale()` hook |
| `components/LocaleSwitcher.tsx` | Globe dropdown in the nav |

## Usage patterns

**Client component**
```tsx
const { copy, locale } = useLocale();
const extra = getExtraCopy(locale);
<h1>{copy.missions.title}</h1>
<p>{extra.errors.loadMissions}</p>
<span>{localizeZone(mission.zone, locale)}</span>
<time>{formatDateForLocale(mission.start_date, locale)}</time>
```

**Server component**
```tsx
const copy = await getRequestCopy();
const extra = getExtraCopy(await getRequestLocale());
```

## Stored values vs displayed labels

Enum-like columns keep their **French canonical strings** in Postgres, and the DB `check` constraints depend on them:

- `missions.type` ∈ `'À la journée' | 'À la semaine' | 'Saisonnier' | 'Convoyage' | 'Autre'`
- zones / boat types are free `text[]` but the UI only offers `NAVIGATION_ZONES` / `SKIPPER_BOAT_TYPES` from `lib/profile-options.ts`

Never store a translated label. Add new zones/boat types to `lib/profile-options.ts` **and** to the label maps in `lib/i18n/options.ts`.

Language names on skipper profiles (`profiles.languages`) are ISO‑639‑1 **English names** from the `iso-639-1` package (`LANGUAGE_OPTIONS`), sorted with French collation, and are displayed as-is in every locale.

## Adding a string

1. Add the key to the `fr` block in `copy.ts` (or to the `ExtraCopy` type + `fr` block in `extra.ts` if it is an error/legal/profile string).
2. Add the same key to the other nine locales. In `extra.ts` the compiler forces you; in `copy.ts` it does not — grep to double check.
3. Consume it via `copy.x.y` / `extra.x.y`. Avoid string literals in JSX.

## Adding a locale

1. Append `{ code, flag, label }` to `LOCALES` in `locales.ts`.
2. Add the `Intl` tag in `format.ts`.
3. Add a full block in `copy.ts`, `extra.ts`, `options.ts` (every label map), and `PHONE_COPY` in `phone.ts`.
4. TypeScript will flag missing entries in `extra.ts`, `options.ts` and `phone.ts` (all typed `Record<SupportedLocale, …>`); `copy.ts` must be checked manually.

## Known limitations

- Pluralisation is binary (`unread` / `unreadPlural`), no ICU.
- Some legal text was translitterated without diacritics in several locales (e.g. Danish `Brugsvilkar`, French `Verification du profil`), presumably to avoid encoding issues — review before a marketing launch.
- Legal pages state `Sidst opdateret: 2026-09-08` etc. as hard-coded strings per locale.
- No RTL support (none of the shipped locales need it).
